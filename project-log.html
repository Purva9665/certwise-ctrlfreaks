What we built

Input

  • Certificate name (typos are fine - edit distance, Levenshtein, dynamic programming).
  • Verification link or certificate ID - or the certificate file: PNG, JPG, WEBP or PDF, up to 5 MB. Images are scanned for a QR code (jsQR); PDFs for a QR code on the first 3 pages and for clickable or printed links (pdf.js). Other file types and bigger files are refused with a clear message. Everything runs in the browser - the file is never uploaded.
  • Or scan the QR code with the camera (best on a phone): the back camera opens, a frame is checked four times a second, and the camera switches off as soon as a code is found.
  • Optional: the college / institute that issued it.
  • Just a link: for Credly, Coursera and edX the certificate does not have to be in our list - its name, issuer and how it is earned come from the issuer's own record, and it is scored from that.
  • No readable record? Three quick questions - who issued it, how it was earned, does it have a verification link or ID - and the same score is worked out from the answers, clearly marked as based on the user's answers.
  • Download report: every result can be saved as a one-page PDF with clickable proof links.

Answer 1 - Is it genuine?

  • Official verification link - the link is on the issuer's own verification site (domain + path checked).
  • Look-alike website - the link copies the issuer's name or is a small typo of it (coursera-verify.com, credlly.com).
  • ID looks right / doesn't match the format - e.g. Red Hat 123-456-789, then the official page to confirm.
  • Can't be verified - certificate types with no official record.
  • Fake university - issuer matched against UGC's list of 32 (typos allowed).
  • We never say "100% genuine" - the last step is always the issuer's own page, linked with one button.
